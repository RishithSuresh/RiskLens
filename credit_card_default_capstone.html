04 / research notes

Method and operating guardrails

A reproducible scikit-learn workflow with leakage-safe preprocessing and stratified validation.

Data quality & design

  • 0 duplicate rows and 0 missing values in the supplied data.
  • ID was retained for auditability but excluded from predictors.
  • 3 categorical features were one-hot encoded; 20 numeric features were imputed and standardized.
  • 80/20 stratified split: 24,000 train rows and 6,000 test rows.

Statistical evidence

  • Education, sex, and marriage were all statistically associated with outcome; the largest Cramer's V was education at 0.074.
  • PAY_0 median: 0 for no-default accounts vs 1 for default accounts.
  • LIMIT_BAL median: 150,000 for no-default accounts vs 90,000 for default accounts.
  • All reported findings are associations, not causal claims.

Recommendations

  • Use the model to prioritize interventions, not as an automatic adverse-action decision.
  • Select a production threshold from an explicit cost matrix.
  • Monitor recall, precision, PR-AUC, calibration, and subgroup performance.

Limitations

  • Observational, cross-sectional data may not reflect time-dependent deployment behavior.
  • Category codes include unusual or undocumented values.
  • No external economic variables or temporal validation are included.

06 / operating policy

Thresholds are a choice

The default 0.50 cutoff is only one operating point. The notebook selects an alternate cutoff on a validation split by maximizing F2, then evaluates it once on the untouched test split.

09 / responsible use

Before deployment

  • Run temporal validation on a later portfolio period.
  • Calibrate probabilities and monitor drift.
  • Review subgroup metrics with compliance stakeholders.
  • Document threshold economics and override rules.
  • Keep a human in the decision loop.
